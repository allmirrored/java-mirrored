T1 хранит текущую и максимальную длину серии, один проход, O(n) времени,
O(1) дополнительной памяти. Ноль сбрасывает текущую длину.
T2 перебирает пары i < j, O(n²) времени и O(1) дополнительной памяти.
При n <= 50 это максимум 1225 пар; сортировать список не требуется.
Строгое сравнение < не включает сумму, равную target. Пустые массивы
не входят в условия обеих задач; тестируются минимальная длина 1,
максимальные длины и значения, оба примера отдельными тестами.

## Учебная последовательность

1. LeetCode: готовый код в leetcode.md, Accepted-снимки в screenshots/h08.
2. DevOps: локальная/экспортированная переменная, дочерний bash, PATH,
   собственная программа hello, временные и постоянные настройки, aliases,
   EDITOR и type. Скриншоты делаем по отметкам в чате.
3. Git: отдельная песочница /tmp/undo-demo-h08. Amend, forgotten file,
   два restore, soft/mixed/hard reset, reflog, revert. Эти действия не
   выполняются в java-template. До разрушительных шагов проверяем pwd
   и содержимое учебных файлов.
4. Обсуждение вопросов, add, staged diff, отдельный коммит h08, push,
   проверка файлов на GitHub.

В этом терминале Bash, поэтому ~/.zshrc не используется. Перед постоянными
изменениями проверяем существующие ~/.bashrc и ~/.bash_profile, сохраняем
их копии и выясняем, какие файлы реально читаются при запуске Git Bash.
Oh My Zsh предназначен для Zsh; не устанавливаем его в Bash и не выдаём
prompt Git Bash за выполнение пункта про Oh My Zsh. Этот пункт разберём
отдельно после проверки доступной среды.

Не публикуем полный env вслепую: сначала проверяем вывод локально,
поскольку программы могут хранить в окружении токены. Для учебного
снимка достаточно явно выбранных несекретных переменных.

Настройка EDITOR=nano имеет смысл только при установленном nano;
сначала проверяем command -v nano. Глобальный core.editor меняем только
в рамках этого шага, после проверки существующего значения.
