## DevOps: артефакти

Виконуємо в збереженій лабораторії /tmp/build-lab-h09/demo, поза проєктом.
Це продовження demo з заняття 9; його pom.xml можна змінювати.
JDK і Maven підключаємо через source /c/gethub/java-template/doc/h07/environment.sh.

1. mvn package і jar з назвою demo-1.0.0.jar.
2. unzip -l, читання MANIFEST.MF, очікувана помилка java -jar без Main-Class.
3. Додати maven-jar-plugin лише в навчальний pom.xml, зібрати повторно,
   перевірити Main-Class і запуск java -jar. Для кирилиці в Git Bash:
   java -Dstdout.encoding=UTF-8 -jar target/demo-1.0.0.jar | cat.
4. SHA-256 оригіналу та окремої копії /tmp/received-h10.jar. Додати нульовий
   байт тільки до копії, повторити хеш. Дописування байта змінює байти файла,
   але ZIP-програми можуть і далі його читати; це не гарантує помилку відкриття.
   sha256sum є рівноцінною заміною shasum -a 256.
5. ZIP і tar.gz релізу, список вмісту. У поточному Git Bash знайдені
   unzip, tar і sha256sum; zip треба перевірити/встановити через окремий MSYS2,
   не підміняти виконання zip неперевіреним звітом.
6. Git init тільки в навчальному demo. Порівняти status до/після
   створення його .gitignore з target/. clean і package відновлюють артефакт.
   Це перевірка можливості повторної збірки, а не гарантія побайтово однакових
   JAR: для детермінованих архівів окремо налаштовують timestamps та інші входи.

## Git: merge

Окрема неопублікована песочниця /tmp/merge-demo-h10 з git init -b main.
Ідентичність автора встановлюємо локально з останнього комміта
основного проєкту. Основна repository-cleanup не є місцем цих вправ.

1. База, feature, зміна f.txt, повернення main, merge --ff-only feature:
   явне підтвердження fast-forward без нового комміта.
2. reset --hard HEAD~1 тільки в цій песочниці. feature залишається на старій
   вершині. feature2 змінює other.txt, main змінює main-only.txt.
   merge feature2 --no-edit створює комміт злиття.
3. cat-file -p HEAD: два parent; порівняти з вершинами перед злиттям.
   Загалом Git підтримує й merge з більш ніж двома батьками, але ця вправа
   показує злиття саме двох гілок.
4. feature3, зміна f.txt, merge --no-ff: примусовий merge-комміт.
5. feature4 і паралельний main, merge --ff-only feature4: очікувана відмова.
6. branch --merged, видалення підтверджено влитих feature2 і feature3.
   feature після reset з пункту 2 більше не є влитою в поточний main;
   branch -d feature може закономірно відмовити. feature4 теж невлита.
   Не називаємо їх влитими й не застосовуємо -D до основного проєкту.
   Долю цих навчальних гілок розбираємо за фактичним графом.

При кожному етапі команди і момент скриншота даються в чаті.
Навчальні JAR, ZIP, tar.gz, target і вкладені .git не додаються
до персонального репозиторію. У нього йдуть рішення, тести й скриншоти h10.
