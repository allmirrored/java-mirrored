## DevOps: последовательность и смысл

Рабочая папка с тестовой страницей: `extra/labs/h07/files-lab`.
Она заменяет `~/dev/files-lab` из методички, команды выполняют ту же задачу.

1. Запустить сервер и найти слушающий процесс. Понять связь адреса,
   порта и PID. Снимок `devops-8.png`: запуск и проверка слушателя.
2. Сделать запросы к localhost и 127.0.0.1, затем `curl -i`.
   Понять HTTP-заголовки и код 200.
3. Запросить отсутствующий путь и порт без сервера. Различить ответ 404
   и невозможность установить соединение. Снимок `devops-9.png`.
4. Воспроизвести конфликт порта, определить процесс, остановить только
   свой сервер и повторно запустить его. Понять диагностику конфликта.
5. Посмотреть все слушающие порты и проверить возможность TCP-соединения.
6. Остановить свой сервер и подтвердить, что порт освобождён.
   Снимок `devops-10.png`: завершение и проверка порта.

Команды выдаются по шагам в чате после просмотра результата предыдущего.
На каждом снимке нужны команды, вывод и имя пользователя или дата/время.
При необходимости делаем больше трёх снимков, чтобы не обрезать вывод.

### Отличия Windows от Linux

В этой установке Git Bash нет `lsof`, `nc` и Linux `ss`.
Не следует изображать их успешное выполнение. Для Windows можно получить
тот же смысл другими командами; если преподаватель требует буквально
Linux-команды, нужно согласовать Windows-эквиваленты либо использовать Linux.

| Методичка | Windows/Git Bash | Что узнаём |
| --- | --- | --- |
| `lsof -i :8000` | `netstat.exe -ano -p tcp \| grep ':8000'` | Адрес, порт, состояние, Windows PID в последнем столбце |
| `lsof -nP -iTCP -sTCP:LISTEN` | `netstat.exe -ano -p tcp \| grep LISTENING` | Все TCP-слушатели |
| `nc -z` | Python `socket.connect_ex`, команда будет дана в чате | Есть ли TCP-соединение; код завершения |
| `kill <PID>` | Для Windows PID: `taskkill.exe //PID ЧИСЛО //T` | Завершение своего процесса; двойной `/` нужен из-за преобразования путей MSYS |

Не подставлять неизвестный PID и не останавливать чужие процессы.
Номер фонового задания Bash `%1` и Windows PID — разные сущности.
`jobs` показывает задания только текущего окна Bash.

## Git: отдельная учебная песочница

Трек требует временный демонстрационный репозиторий `/tmp/diff-demo`.
Это упражнение из методички, а не новый репозиторий для сдачи домашних работ.
В основном проекте вложенную `.git` не создаём. Git-команды упражнения
студент выполняет самостоятельно в этой временной папке.

| Команда | Сравнение |
| --- | --- |
| `git diff` | Рабочие файлы против индекса |
| `git diff --staged` | Индекс против последнего коммита |
| `git diff HEAD` | Рабочие файлы против последнего коммита |

Проходим все 8 пунктов методички: unstaged/staged, смешанные изменения,
hunk и `-U`, сравнение коммитов, ограничение пути через `--`, `--stat`,
`--word-diff`, просмотр перед коммитом. Скриншоты:

- `git-9.png`: после `add` обычный diff пуст, staged diff показывает правку.
- `git-10.png`: staged и unstaged одновременно; все три сравнения различаются.
- `git-11.png`: сравнение коммитов и word diff; при необходимости ещё снимки.

Новые номера выбраны, чтобы сохранить существующие фотографии h07.
Старые восемь Git-фотографий h07 дублировали h06 и удалены после выполнения трека.

## Открытая дискуссия

После треков студент формулирует своими словами:

1. `x = x + 1`: прочитать значение, вычислить сумму, записать обратно.
2. `=` присваивает, `==` сравнивает; в Java результат сравнения — boolean.
3. `for` удобен для счётчика/перебора, `while` — пока выполняется условие.
4. Условий и циклов достаточно для выражения алгоритмов при наличии
   операций с данными; сложность и удобство записи при этом различаются.
5. `break` завершает ближайший цикл; оценивать нужно понятность условия выхода.
6. Для завершения цикла нужна величина, которая приближается к границе:
   например, положительное `number` в Number of Steps постоянно уменьшается.
