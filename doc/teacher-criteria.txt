Критерії до коду в репозиторії студента
Критерії перевіряються на репозиторії, створеному з java-template. Кожен критерій має номер і
або виконується, або ні; проміжних оцінок немає. Перевірка йде в порядку номерів: якщо не
виконано критерій групи A, наступні групи не перевіряються.
A. Репозиторій
№ Критерій Перевірка
A1 Увесь код усіх домашніх робіт лежить в одному репозиторії одне посилання на
репозиторій додано до
першої або нульової роботи

A2 Репозиторій створено з java-template; pom.xml і
.gitignore не змінено
A3 У репозиторії немає згенерованих і службових файлів:
target/, .idea/, *.iml, .DS_Store
A4 Репозиторій відкритий для викладача (public або доступ
наданий)

відкрити посилання

A5 Для кожної домашньої роботи hNN є щонайменше один
коміт, який додає її файли й не зачіпає інші hNN; подальші
коміти з виправленнями попередніх робіт дозволені
A6 Файли не завантажувалися й не видалялися через веб-
інтерфейс GitHub; робота йде лише зчерез: git add, git
commit, git push
B. Структура
№ Критерій Приклад
B1 Розв&#39;язок задачі – один клас у
src/main/java/homework/hNN/, де NN –
номер заняття з нулем (h01, h12)

src/main/java/homework/h03/T1.java

B2 Тест – один клас у src/test/java/ з тим
самим пакетом і назвою &lt;Клас&gt;Test

src/test/java/homework/h03/T1Test.java

B3 T1 – перша задача заняття, T2 – друга; інших
назв класів задач немає

T1, T2

B4 Код лежить лише в src/main (розв&#39;язки) і
src/test (тести); у корені немає .java

find . -maxdepth 1 -name &#39;*.java&#39; –
порожньо

B5 Каталоги app/ і code/ із шаблону не змінено
і не видалено

git diff &lt;template&gt; --
src/*/java/{app,code}

B6 У src/ лише файли .java: ні .txt, .md,
.png, .class, ні архівів, ні даних

find src -type f ! -name &#39;*.java&#39; –
порожньо

B7 Усі інші файли (нотатки, .md, скриншоти,
дані тощо) лежать в окремому каталозі
поруч із src/ (doc/, screenshots/, extra/,
other/); у корені лише src/, pom.xml,
.gitignore, readme.md із шаблону та такі
каталоги

ls -A кореня

C. Іменування
№ Критерій

C1 Пакети – малі літери без підкреслень (homework.h03)
C2 Класи – UpperCamelCase; методи і змінні – lowerCamelCase; константи – UPPER_SNAKE_CASE
C3 Назви файлів і каталогів – лише ASCII, без пробілів, кирилиці й великих літер у назвах
каталогів
C4 Назви методів тестів описують поведінку (returnsZeroForEmptyInput), а не номер (test1)
C5 Однолітерні імена змінних дозволені лише для індексів циклу (i, j) і в лямбдах
C6 Назва файлу збігається з назвою публічного класу в ньому (T1.java – class T1), а package
збігається зі шляхом каталогу
D. Документування
№ Критерій
D1 Безпосередньо перед оголошенням кожного класу задачі (після package та import) стоїть
коментар // https://leetcode.com/problems/&lt;slug&gt;/ із прямим URL задачі
D2 URL збігається із задачею, виданою для цього заняття в classroom
D3 У коді немає закоментованого коду, TODO, System.out.println для налагодження
D4 Код не містить коментарів (//, /* */, Javadoc), крім URL із D1; змістовні порожні рядки
між логічними блоками дозволені
E. Збірка
Команди запускаються з кореня репозиторію на JDK 25 (як у pom.xml). Перевірка виконується на
чистій копії: git clone + команда, без файлів, яких немає в git.
№ Критерій Команда Очікуваний результат
E1 Код компілюється mvn clean
compile

BUILD SUCCESS
E2 Тести компілюються mvn test-compile BUILD SUCCESS
E3 Усі тести проходять mvn test Failures: 0, Errors: 0,

Skipped: 0

E4 Форматування відповідає google-
java-format

mvn
spotless:check

BUILD SUCCESS

F. Тести
№ Критерій
F1 Для кожного класу задачі, що має розв&#39;язок, існує тестовий клас (B2)
F2 Кожна гілка коду розв&#39;язку (if, else, case, умова циклу, тернарний оператор) виконується
хоча б одним тестом
F3 Є тест для кожної межі з умови задачі: мінімальне і максимальне допустиме значення,
порожній вхід, один елемент (де застосовно)
F4 Кожен тест містить хоча б одну перевірку assertThat(...) або assertThatThrownBy(...)
(AssertJ)
F5 Приклади з умови задачі LeetCode (Example 1, Example 2, …) є окремими тестами
F6 Тести не залежать від порядку виконання, файлів, мережі, поточного часу й випадкових
значень без фіксованого seed
G. Скриншоти
Файли лежать у каталозі screenshots/ поруч із src/ (B7), по підкаталогу hNN/ на заняття;
формат – .png або .jpg. На скриншоті видно дату й час або імʼя користувача.

№ Критерій Файл
G1 Для кожної задачі T1, T2 кожного заняття є
щонайменше один скриншот сторінки LeetCode зі
статусом Accepted, де видно номер і назву задачі

screenshots/h03/T1-
leetcode.png

G2 Для кожного заняття є щонайменше 2-3 скриншоти
виконання треку Git: термінал із командами та їхнім
виводом

screenshots/h03/git-1.png,
git-2.png

G3 Для кожного заняття є щонайменше 2-3 скриншоти
виконання треку DevOps: термінал із командами та
їхнім виводом

screenshots/h03/devops-1.png,
devops-2.png

G4 Є один скриншот профілю LeetCode із загальною
кількістю розв&#39;язаних задач; ця кількість не менша за
кількість задач T1 і T2 у репозиторії

screenshots/leetcode-
